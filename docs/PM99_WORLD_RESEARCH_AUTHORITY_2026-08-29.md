## Non-negotiable guardrails

- Mode `0` and mode `1` describe different EQ record layouts. They do not
  mean English/foreign, playable/non-playable, country or division.
- Do not promote a field because it parses. A write must have a bounded span,
  reopen validation and a visible game proof in the same record family.
- Do not use success exit codes, a final scripted step or an OCR match from a
  search result as proof. The actual game screen must identify the intended
  player, club or competition.
- Do not use `attr0..attr2`, unknown player tails, manager biography text,
  guessed competition bytes, or untraced kit/tactics data as editor fields.
- A club's competition placement is a whole-carrier transaction, not a guessed
  EQ `division` byte. The English 92 method is documented separately and does
  not prove a foreign-country equivalent.
- A live mode-1 external roster row becomes a real move only as a constrained
  source-and-target transaction. The 2026-08-29 Barcelona/Raúl control proves
  both profile-club resolution and the danger of leaving a duplicate link.
  Preserve row count/flags and reject duplicate JUG ids in generated data.
- A modern carrier's final existing `EQ -> ENT` manager ID is writable in
  modes 0 and 1 only as a replacement with an existing ENT ID. Preserve the
  list count and preceding IDs. Variable-length manager surnames are proven;
  full-profile display names and manager biography text remain preserve-only.
- The old safe-read/edit matrix remains useful for its date and scope, but its
  new scope-correction notice means it cannot overrule this page for world
  work.
