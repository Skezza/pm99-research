# Calendar-year source correction

The collector used the game season's start year as Transfermarkt's season ID
for every country. For Brazil, Ireland, Norway and Sweden, retained pages show
that this selected fixtures from the following calendar year. The game year and
the provider's numeric season ID must be separate values.

For example, the retained Botafogo schedule requested with provider ID 2016
contains its opening fixture dated 2017-05-14, match 2846995. Provider ID 2017
contains the following year's schedule. The metadata, original URLs and retained
body hashes are recorded in
[the evidence receipt](../data/transfermarkt-calendar-year-routing-evidence-v1.json).
Transfermarkt is credited as the source; this receipt contains research metadata,
not game binaries or the full captured pages.

## What the collector now does

For the four explicitly mapped competitions, it requests provider ID `year - 1`.
That is a request strategy, not proof that a response is correct. Acceptance also
requires the actual captured page title and opening fixture date to identify the
requested calendar year. A wrong year, missing title or unavailable response
produces a reported gap. Country and competition must agree. The allocated-lineup
reader preserves the target year, provider ID, policy and evidence binding in its
output rather than silently dropping the route metadata.

Corrected requests use versioned cache keys. Existing snapshots and SOURCE
ancestors are preserved. European split-season requests retain their existing
route and cache keys. Russia through 2010 remains explicitly unresolved pending
separate transition-period evidence; this change does not guess its mapping.

The policy can attempt a fresh year such as 1990 without a hardcoded year list.
It still needs responses that pass the same title and fixture checks. This does
not promise that all historical data exists or that a recipe is complete.

## Delivery boundary

**The collector correction does not repair an already installed game.** Those
repairs need separately reviewed source inputs, carrier assignments, native
changes and runtime evidence. The 931 mismatched source rows are an audit scope,
not 931 independently verified native bugs. The original 2015 legacy source set
is outside this Transfermarkt audit and must be preserved.

The local reuse index found 865 retained schedule/report pairs across 23 previous
plans. The boundary inputs for target years 2000 and 2016 were not retained in
that plan series. Older squad inputs also use different source formats, so a
matching fixture does not by itself prove a complete, usable squad capture.

Repair only the affected country slices. Preserve unrelated players, clubs,
managers, tactics, assets and current preferred releases. Re-key imported source
and proof artifacts so a corrected slice cannot overwrite existing provenance.
The existing package builder's blocked partial draft is an authoring input, not
a releasable whole-season package; do not disable its completeness checks.

```sh
  scripts/test_transfermarkt_calendar_year_policy_v1.py \
  scripts/test_capture_transfermarkt_opening_lineups_v1.py \
  scripts/test_capture_transfermarkt_historical_squads_v1.py \
  scripts/test_capture_allocated_opening_lineups_v1.py \
  scripts/test_plan_transfermarkt_opening_lineups_batch_v1.py
```

An independent Luna review found the allocated-output provenance omission;
it was fixed and covered by an additional test using the retained Botafogo
schedule. That test mocks report parsing and does not certify the real report.
The earlier private candidates and negative test results remain in the local
audit evidence. No existing games were regenerated by this collector change.
