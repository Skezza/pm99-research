# Narrow position and Handling corrections

These corrections use the existing bounded publisher and native writers. They
preserve the parent release and do not recalibrate the rest of a season.

`season_annual_literal_broad_position_v1` accepts an explicit case bound to its
registered parent, raw FootballSquads club file and captured annual dataset.
The original club file is reparsed. Full name, literal date of birth, source
club/country and exclusive native ownership must agree. The existing fine role
must already be compatible with the sourced broad position. The supported
native lane is `dd6361`, with its proven broad-position byte at `name_end+11`.
The adjacent byte, fine roles, abilities and all other facts remain unchanged.
An audit finding is not source authority; no private audit filename is required.

`season_selected_outfield_handling_cap_v1` accepts explicit selected actors with
their name, birthday, owner and old Handling value. Both recipe and native data
must identify an outfield player whose Handling exceeds 20. It caps that value
at 20 and retains all nine other abilities. This is a declared editorial rule,
not a claim that the resulting ability is a sourced historical measurement.
The immutable request hash namespaces the source receipt, allowing subsequent
independent corrections without changing an earlier receipt.

The latter provider feeds the existing quality-only writer. Existing source and
rating policies retain their default behavior. The publisher and SOURCE replay
retain their default eight-GiB reserve; the reviewed six-GiB minimum is available
only through an explicit argument.

## Goalkeeper input and detailed-role consistency

The source-package builder maps a literal source `G` to fine role `[0]`. Broad
outfield positions retain their existing policy because they do not determine a
side or a detailed position. This avoids copying a previous carrier's outfield
role onto a newly authored goalkeeper.

For existing recipes, `season_sourced_goalkeeper_roles_v1.prepare_position_consistency`
plans the same derived correction where the recipe explicitly declares `G`,
native readback agrees on the player name and broad `G`, and the recipe still
preserves inherited fine roles. It closes explicit fine-role declarations and
whole-person fallbacks. The result records its separate consistency policy;
the older original-source/DOB admission policy remains available unchanged.

This derives the detailed keeper role from an existing position declaration.
It does not independently certify that person's historical identity, club or
position. Missing secondary facts stay missing or preserved. The writer changes
only the six fine-role bytes and the recipe's fine-role field, preserving all
abilities, biography, names, ownership, orders, tactics, kits and photographs.
SOURCE recomputes the exact plan from the immutable parent, rejects unresolved
or mixed transactions, and compares the full game inventory and recipe. Genuine
runner evidence must establish the visible keeper label before installation.
New consistency receipts use hash-namespaced input filenames and proof IDs,
preserving earlier role corrections and their source artifacts in the recipe.

Before installation, check full recipe validity, exact native changes,
unselected records and file inventories, an actual independent SOURCE build,
and relevant runner evidence. A prepared or built candidate is not an installed
correction. Existing fallback facts are not silently upgraded to verified facts.
