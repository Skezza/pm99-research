# Preserving native fields during foreign identity moves

The existing foreign mode-1 identity exchange keeps native carrier membership,
EQ bytes and opaque opening controls fixed. Dated ownership evidence authorizes
moving person identities between those slots. Names, sourced facts and each
person's skills follow the identity; unrelated records remain unchanged.

When a source recipe explicitly preserves its fine roles, the exchange records
that source person's actual six native role slots. It only admits a nonempty,
unique, packed sequence of supported roles followed by empty slots. Apply checks
the source preimage, passes the measured values through a temporary compiler
view, and verifies all six destination slots afterwards. The saved recipe keeps
its preservation marker. This preserves existing roles; it does not certify
that those roles are historically correct or replace the separate editorial
role-correction policy. No new binary writer is involved.

An explicitly preserved nationality remains the exact destination native byte,
as in the core compiler's existing preservation contract. Readback compares
that byte directly instead of treating the policy dictionary as a country code.
This is not evidence of historical nationality. Sourced country strings still
require their ordinary encoded-country readback.

Moving a person may require the separately proven same-carrier name-capacity
recovery; it needs its existing explicit request and runtime-backed bundle.
Fallback notes remain field-sorted and unique. Any unsupported role sequence,
name overflow, changed preimage or unrelated native modification fails before
publication. SOURCE reconstruction replays the same guards.
